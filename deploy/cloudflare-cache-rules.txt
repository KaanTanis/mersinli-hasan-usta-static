Cloudflare — basit cache rehberi (Cache Rules, güncel panel)
Site: mersinlihasanustatantuni.com (statik HTML + /assets)

Kaynak: https://developers.cloudflare.com/cache/how-to/cache-rules/

═══════════════════════════════════════════════════════════════
ÖNCE ANLA: İKİ KATMAN
═══════════════════════════════════════════════════════════════

1) Origin (nginx) → Cache-Control header gönderir.
2) Cloudflare edge → Bu header'lara göre (veya kurala göre) saklar.

Sizin nginx conf zaten doğru:
  index.html  → max-age=0, must-revalidate
  /assets/*   → max-age=31536000, immutable

Cloudflare'de çoğu iş için sadece 2 Cache Rule yeterli.

═══════════════════════════════════════════════════════════════
PANEL YOLU (2026)
═══════════════════════════════════════════════════════════════

Cache Rules:
  Dashboard → Caching → Cache Rules → Create rule
  (Doğrudan: https://dash.cloudflare.com → domain seç → Caching → Cache Rules)

Genel cache ayarı:
  Caching → Configuration → Caching level → Standard (Default)

Deploy sonrası temizlik:
  Caching → Purge Cache → Custom Purge → URL → https://www.mersinlihasanustatantuni.com/

Geçici test (tüm site cache kapalı ~3 saat):
  Caching → Configuration → Development Mode → On

Not: Eski "Page Rules" yerine Cache Rules kullanın.

═══════════════════════════════════════════════════════════════
KURAL 1 — Ana sayfa (HTML) cache'e girmesin
═══════════════════════════════════════════════════════════════

Rule name: Bypass HTML homepage

When incoming requests match:
  Custom filter expression → Edit expression:

  (http.request.uri.path eq "/" or http.request.uri.path eq "/index.html")

Then:
  Cache eligibility → Bypass cache

Place at: First (en üstte)

Deploy

Açıklama: Bypass cache seçince Cloudflare o isteği edge'de tutmaz;
site güncellemesi hemen görünür (purge şart değil, yine de alışkanlık olarak purge edebilirsiniz).

═══════════════════════════════════════════════════════════════
KURAL 2 — /assets uzun süre edge'de kalsın
═══════════════════════════════════════════════════════════════

Rule name: Cache assets long

When incoming requests match:
  Custom filter expression:

  starts_with(http.request.uri.path, "/assets/")

Then:
  Cache eligibility → Eligible for cache

  Edge TTL →
    "Use cache-control header if present, use default Cloudflare caching behavior if not"
    (API adı: respect_origin — origin'deki 1 yıl header'ını kullanır)

  Browser TTL → Respect origin

Place at: Second

Deploy

═══════════════════════════════════════════════════════════════
OPSIYONEL KURAL 3 — robots / sitemap / llms
═══════════════════════════════════════════════════════════════

Çoğu planda gerekmez; nginx zaten kısa TTL veriyor.
İsterseniz:

Expression:
  (http.request.uri.path eq "/robots.txt" or http.request.uri.path eq "/sitemap.xml" or http.request.uri.path eq "/llms.txt")

Then: Eligible for cache + Edge TTL respect origin

═══════════════════════════════════════════════════════════════
CACHE RESPONSE RULES — ŞİMDİLİK DOKUNMAYIN
═══════════════════════════════════════════════════════════════

Aynı sayfada "Cache Response Rules" sekmesi var (origin cevabından sonra
Cache-Control değiştirmek için). Nginx header'ları doğruysa gerek yok.

═══════════════════════════════════════════════════════════════
HIZ (Speed) — AYRI MENÜ, CACHE RULE DEĞİL
═══════════════════════════════════════════════════════════════

Speed → Optimization (veya Settings → Speed)

  • Brotli / sıkıştırma: planda varsayılan açık (Free: Zstandard, Pro+: Brotli)
  • HTTP/3: Network veya Speed altında (zone ayarı)

HTML'de inline CSS olduğu için Auto Minify HTML'i açmayın (eski özellikler
kaldırıldıysa zaten yoktur; Compression Rules dokümanına bakın).
